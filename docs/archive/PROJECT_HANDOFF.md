## 최우선 최신 상태: PC 원본 DB 연결 (2026-11-07)

사용자는 기존 PC 견적 프로젝트에 CPU·메인보드·RAM 등 모든 견적 부품의 실제 DB를 연결하는 것이 우선이라고 정정했다. 이어 TechSpecs 추가 유료 호출 없이 무료 데이터만 연결하도록 선택했다.

- BuildCores 공개 원본에서 실제 제품 **47,436개, 23종**을 SQLite에 저장했다. CPU 790/메인보드 3,701/RAM 4,876/GPU 3,865/스토리지 3,505/파워 3,308/쿨러 2,423/케이스 3,808개와 기타 품목을 포함한다.
- `/devices`는 이제 CPU를 기본으로 표시하며 모든 PC 부품·완제품·주변기기를 검색한다. 기존 견적 부품 선택/DB 자동완성도 같은 DB를 읽는다.
- 기존 견적/AI 어드바이저/교체 코드의 PC 제품 조회에 로컬 DB를 연결했다. 추천 가격·FPS는 기존 알고리즘의 추정값이라고 명시했다. 국내 실제 가격은 미연결이다.
- 노트북 등 일부 데이터는 제품명/모델만 있고 상세 사양은 부족하다. 원본 DB 전체를 국내 판매 확인 제품으로 주장하지 않는다.
- TechSpecs 이번 추가 호출 0회. 스마트폰 3개 공개 유지, 태블릿/워치 0개 유지. 유료 수집은 새 비용 승인 전 중단.
- [DATA_SOURCES.md](../DATA_SOURCES.md)에 전체 수량·출처·라이선스·복원 명령·미구현 사항을 정리했다. 다른 PC에서는 `back`에서 `npm run sync:parts`로 무료 DB를 복원한다.
- 키/실제 DB는 Git 제외이며 코드도 아직 GitHub에 반영되지 않았다.
- 검증: 기존 기기 테스트 25개 + PC DB 테스트 8개 통과, 프론트 빌드 성공. 실행 서버를 통해 23개 DB 품목/8개 견적 검색 분류/한글 모델 검색/페이지 이동/스마트폰 비교를 확인했다. 150만 원 견적 HTTP 200에서 8개 모두 원본 `opendb_` ID와 예상 가격 표식을 확인했다.

**아래는 이전 단계 기록이며, 충돌하는 내용은 이 절과 DATA_SOURCES.md가 우선한다.**

## 현재 주제와 최신 결과 (2026-11-07)

프로젝트는 기존 PC 견적·부품 추천을 유지하면서 IT 기기 비교·대여로 확장한다.
nofee.team의 기기 선택→나란히 비교 흐름을 참고해 스마트폰·태블릿·스마트워치 비교 화면을 구현했다.
사용자가 실제 비교 검증을 위해 국내 모델 3개 수집을 새로 승인했고, 해당 상세 API 3회를 실행했다.

- 국내 Galaxy S24/S24+/S24 Ultra 모델 3개를 실제 TechSpecs에서 수집해 로컬 DB에 저장.
- 삼성 공식 모델 표와 대조 후 국내 정발 근거를 저장해 공개 검색에 표시.
- `/devices`에서 한글 제품명 및 모델 코드 검색 가능.
- `/devices/compare`에서 최대 3개 선택, 핵심/전체 사양, 다른 항목 필터, 링크 공유 구현.
- 비교/검색은 로컬 DB 또는 설정된 Supabase를 읽으며 외부 API를 매번 호출하지 않음.
- 최근 4년은 모바일 3개 분류에 자동 적용, 스마트폰은 정발 검수 제품만 공개.
- 태블릿/스마트워치의 실제 데이터 수집, 전체 브랜드 수집, 국내 가격, 벤치마크, 대여 기능은 아직 미완료.
- TechSpecs S24 충전 전력 오류 1건을 공식 출처로 검수해 핵심 표에 원본과 함께 표시.
- 백엔드 25개 테스트 및 프론트엔드 빌드 확인. 실제 브라우저에서 2/3개 비교와 차이점 필터 검증.
- 실제 키와 제공 데이터는 Git에서 제외. 변경 코드는 아직 GitHub 미반영.

**아래 내용은 과거 기록이며, 0개 제품/수집 중단 상태보다 위 최신 결과가 우선한다.**

## 최신 변경 (2026-11-07)

**최신 정정:** 브랜드는 전체로 확대했고 기간/조회 방식 선택은 제거했다.
스마트폰·태블릿·스마트워치만 최근 4년 자동 제한, 스마트폰은 국내 정발 근거 확인 제품만 공개한다.
TechSpecs 키를 실제 발급·로컬 저장했고 실제 검색 및 상세 1건 수신에 성공했다.
실제 API 응답 형식(배열 data, 상세 Key Aspects 출시일)에 맞춰 코드를 보정했다.
Supabase가 비어 있어 개발용 SQLite를 연결했다. 실제 W24 중국 모델 1건을 저장했으나 국내 정발 미검증으로 숨겼다.
사용자는 이후 **추가 호출 없이 여기까지 저장**을 선택했다. 허가 없이 추가 TechSpecs 수집을 재개하지 않는다.
현재 공개 스마트폰은 0개이고 대여 기능은 미구현이다. 세부 상태는 TECHSPECS_SETUP.md가 최신이다.
이 아래의 초기 Apple/Samsung 제한·API 키 미발급 설명은 과거 작업 기록이다.

기존 PC 견적 기능을 유지하고 IT 기기 대여를 추가하는 것이 최종 방향이다.
아래 초기 문서의 완제품 비교·추천 확장 논의는 이 방향을 대체하지 않는다.

사용자가 TechSpecs를 선택했으며, 이번 초기 범위는 Apple·Samsung, 출시일 기준 최근 3~4년이다.
사용자는 API 키 발급 전이며 DB 저장 허가를 받았다고 답했다.

이번에 구현한 내용:
- `/devices` 카탈로그 검색/상세 화면과 상단·모바일 메뉴.
- TechSpecs v5 서버 연동, 브랜드·카테고리·출시 기간 검증, 페이징.
- Supabase `device_products` 신규 테이블 SQL 및 상세 데이터 ID 기반 upsert.
- 관리자 전용 페이지 가져오기 API와 제한된 CLI 수집 도구.
- 테스트 17개 통과와 프론트엔드 프로덕션 빌드 성공.

**아직 하지 않은 내용:** 실제 TechSpecs 키로 API 호출, 실제 Supabase 스키마 적용/데이터 저장,
실제 응답 필드 검증, 대여 재고·예약·반납 구현. API/DB 설정이 없어 이 부분은 미완료다.
`TECHSPECS_SETUP.md`에 설정과 실제 데이터 검증 순서를 적었다.
로컬 `back/.env`는 빈 키 입력란으로 준비했고 Git에서 제외된다.
공유 `.env.example`은 실제 키를 포함하지 않는다.

## 새 컴퓨터에서 실행

Node.js 22 기준으로 실행 확인함. 터미널 두 개에서 각각 실행:

```powershell
cd back
npm ci
npm start
```

```powershell
cd front
npm ci
npm run serve
```

- 화면: http://localhost:8080/
- 상태 확인: http://localhost:3000/api/health
- DB 및 외부 서비스는 back/.env.example을 참고해 back/.env에 실제 설정 필요.
- .env와 API 키는 Git에 올리지 않음. 설치된 node_modules도 새 컴퓨터에서 다시 생성.

## 논의 중인 확장 방향 (아직 미구현)

사용자는 전공심화 졸업프로젝트로 노트북·스마트폰·카메라의 목적별 비교·추천 서비스를 고려 중.
기존 조립 PC 서비스의 로그인·저장·커뮤니티 등을 재활용할 수 있으나 동작 검증 필요.

데이터 확보 후보:
- Icecat: 제품별 구조화된 사양. 무료 구독의 실제 국내 모델 포함 여부와 누락률을 표본 확인해야 함.
- 제조사 공식 사양을 바탕으로 필요한 제품의 자체 DB를 구축하고 검수.
- 공개 데이터셋은 라이선스·원출처·지역·최신성을 확인한 뒤 초기 개발용으로 활용.
- 네이버 쇼핑 API는 상세 규격보다는 국내 가격·구매 링크 연동용.

모델 코드, RAM/저장공간 옵션, 국내/해외 모델, 카메라 바디/렌즈 키트를 구분해야 함.
제품 출처 URL과 확인일을 저장하고 누락값을 AI로 지어내지 않는 방향을 추천함.
