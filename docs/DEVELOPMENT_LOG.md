# PC-FIT 개발일지

날짜 대신 구현 흐름을 단계별로 정리합니다. 현재 동작과 남은 작업은 [프로젝트 현황](PROJECT_STATUS.md), 실행 방법은 [학교 셋업](SCHOOL_SETUP.md)을 함께 확인합니다. 이전 상세 기록은 [보관 문서](archive/DEVELOPMENT_LOG_LEGACY.md)에 있습니다.

## 1단계 — 기존 프로젝트 분석과 범위 확정

- PC 견적 생성·추천·부품 교체·호환성 확인 기능을 기반으로 국내 IT 기기 검색·비교를 확장했습니다.
- 스마트폰·노트북·태블릿·스마트워치를 기기 서비스의 네 품목으로 정했습니다.
- 사용자가 검색하기 전부터 등록 제품을 목록으로 탐색하는 구조를 채택했습니다. 대여는 향후 재고·예약·반납 기능으로 확장할 예정입니다.

## 2단계 — 실제 PC 부품 DB 연결

- 무료 BuildCores 원본을 내려받아 정규화하고 SQLite 검색에 연결했습니다. 수집 당시 중복 제거 기준 47,436개, 23개 품목입니다.
- 견적에 CPU·메인보드·RAM·GPU·저장장치·파워·케이스·쿨러를 연결하고 부품 교체 후 합계·전력·호환성을 다시 계산합니다.
- 미확인 가격을 0원으로 취급하지 않고 부분 합계로 표시합니다. 가격과 FPS 추정치는 실판매가나 실측 성능이 아닙니다.
- 출처와 CC BY-NC-SA 4.0 고지를 보존했습니다. 원본은 글로벌 자료이므로 전체 제품의 국내 판매를 보증하지 않습니다.

## 3단계 — TechSpecs 연결과 수집 범위 검증

- 인증·검색·상세 수집·SQLite 저장 흐름을 구현하고 국내 갤럭시 S24 계열 3개를 수집했습니다. 국내 조건에 맞지 않는 중국 모델은 공개 목록에서 제외했습니다.
- 추가 유료 수집은 중단했습니다. 사용자 목록 조회 때마다 유료 API를 호출하지 않습니다.
- API 연결과 공급처 전체 DB 확보는 서로 다른 작업입니다. 수집되지 않은 전체 제품이 자동 등록되는 구조는 아닙니다.

## 4단계 — 국내 공식 자료 기반 기기 카탈로그 보강

- 제조사 공식 사양·사진·국내 출시 근거를 사전 등록하고 로컬 공식 카탈로그 DB를 자동 초기화하도록 구성했습니다.
- 네 품목의 공개 조건을 최근 5년으로 통일했습니다. 서울 날짜 기준으로 범위가 자동 이동하며 국내 출시 근거도 검사합니다.
- 마지막 로컬 공개 집계는 스마트폰 18개, 노트북 22개, 태블릿 14개, 스마트워치 5개입니다. 노트북은 ASUS·Apple·LG·Samsung을 포함합니다.
- Git 제외 TechSpecs DB를 옮기지 않으면 스마트폰 수가 3개 적을 수 있습니다. 국내 전체 모델·용량·색상 SKU가 모두 확보된 상태는 아닙니다.

## 5단계 — 탐색 화면과 비교 흐름 개선

- IT 기기는 /devices, PC 부품·주변기기는 /parts로 나누고 이전 부품 URL의 이동을 처리했습니다.
- 동일 품목 최대 3개 비교, 브랜드 필터, 차이점만 보기, 공유 URL을 연결했습니다.
- 브랜드 변경 시 기존 결과를 지우고 늦게 도착한 응답을 무시하여 타사 제품이 섞이는 문제를 수정했습니다.
- 밝은 배경과 통일된 색상·간격·제품 카드·모바일 비교표를 적용했습니다. 기존 홈 화면은 유지했습니다.
- 디자인 지침을 Vue/Vuetify 구조에 적용했으며 taste-skill 패키지 설치나 전용 자동 검사 완료를 의미하지 않습니다.

## 6단계 — 한국어 상세 사양 표시

- 상세 및 비교 사양의 표시 계층을 한국어 항목명과 단위로 정리하고 성능·디스플레이·카메라·배터리·크기·연결 등의 그룹으로 나눴습니다.
- 제조사 명칭·모델 코드·기술 규격은 보존합니다. 일부 원본 값과 미등록 용어는 영어로 남을 수 있습니다.
- 모두 미확인인 비교 행은 생략하고 일부 제품만 확인된 값은 누락 사실을 표시합니다. 옵션별 수치를 임의로 단일 사양으로 확정하지 않습니다.

## 7단계 — 판매 가격 후보와 가격 이력 화면

- 비공식 danawa-cli 검색을 백엔드에 연결하고 상품명·판매처·가격 후보·판매 페이지 이동을 제공했습니다.
- 네이버 쇼핑은 검색 이동 링크를 제공합니다. 종료된 상품 검색 API나 쇼핑 인사이트 키를 현재 가격 API 연동 성공으로 표시하지 않습니다.
- 쿠팡 API는 연결하지 않았습니다. 동일 용량·자급제·요금제 조건까지 일치하는 최저가 확정은 미완료입니다.
- 가격 이력 화면과 기간 선택을 구현했습니다. 실제 시계열은 미연결이며 사용자가 예시 차트를 선택했을 때만 가상 데이터임을 밝히고 표시합니다.

## 8단계 — 공식 판매처 연결

- 제품 상세와 가격 화면이 공유하는 DeviceOffers에 제조사 공식몰과 SKT·KT·LG U+ 링크를 추가했습니다. 통신사 링크는 스마트폰·태블릿·스마트워치에 표시합니다.
- 확인된 제품 ID와 판매처에만 제품별 구매 주소를 연결했습니다. 현재 iPhone 17·iPhone 16·iPhone Air·iPad(A16)의 Apple 구매 페이지와 Galaxy S24의 SKT 페이지를 등록했습니다.
- 제품 페이지가 미확인인 판매처도 버튼을 유지합니다. 버튼 아래에 “제품 페이지 미확인 · 공식몰 홈으로 이동”을 표시하고 공식몰 홈으로 연결합니다.
- 품절로 확인된 KT S24 페이지와 다른 세대로 바뀐 MacBook Air 공통 구매 주소는 제품별 연결에 사용하지 않았습니다. 해당 판매처 홈 링크는 유지합니다.
- 이는 수동 검수된 링크이며 재고를 실시간 판정하는 기능이 아닙니다. 용량·색상·약정과 판매 종료 여부는 판매처에서 확인해야 합니다.

## 9단계 — 개발 규칙과 검증 정리

- Ponytail 공개 개발 규칙을 루트 AGENTS.md에 적용하고 출처 및 MIT 라이선스를 보존했습니다. 별도의 플러그인 런타임이나 자동 훅을 설치한 것은 아닙니다.
- 이번 변경의 백엔드 테스트 43개와 프론트엔드 테스트 8개가 통과했습니다. 공식 제품 주소 선택, 미확인 모델의 홈 링크 유지, 다른 세대 주소 오연결 방지를 점검했습니다.
- 프론트 프로덕션 빌드가 통과했습니다. 기존 CSS 압축·번들 크기·Browserslist 경고는 남아 있습니다.
- 실제 브라우저에서 iPhone 17과 Galaxy S24 상세의 구매 주소·홈 링크·한국어 안내 표시를 확인했습니다.
- 전체 외부 판매처의 모든 상품 재고, Supabase 회원 흐름 및 미구현 대여 기능을 검증한 것은 아닙니다.

## 10단계 — 문서와 학교 작업 인수인계

- docs에 현황·구조·API·데이터 출처·검증·셋업·개발일지를 정리하고 기존 상세 문서는 archive에 보존했습니다.
- 발표 자료는 기존 문서 폴더에 유지하며 문서의 상대 링크를 갱신했습니다.
- GitHub에 전달할 소스·정적 공식 사양·문서와 별도 이전할 .env·SQLite DB를 구분했습니다. 학교에서는 clone/pull 후 의존성 설치와 필요한 DB 복원을 수행합니다.
- 저장소 업로드 여부는 GitHub 최신 커밋과 로컬 git log를 대조해 확인합니다.

## 남은 작업

- 국내 판매 모델·세부 SKU 확대, 일부 사진 및 옵션 사양 추가 검수.
- 동일 구매 조건의 가격 매칭 및 실제 가격 이력 저장.
- 공식 판매처 링크 재검수와 제품별 주소 확대.
- Supabase 환경 설정 및 회원·저장·게시판 검증.
- 대여 재고·예약·반납·결제 구현.
